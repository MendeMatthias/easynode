# configure time). Installed into the build's Python by
# .github/workflows/btxd-linux.yml with
#
#     pip install --require-hashes --only-binary :all: -r <this file>
#
# and from there bundled into the engine package by engine-python-bundle.py.
# These bytes ship to users, so every file is pinned by hash and nothing is
# built from source: a release that changes one of them has to change this
# file.
#
# Hashes are the sha256 PyPI publishes for each file, read on 2026-11-25:
#
#   cryptography-46.0.4-cp311-abi3-manylinux_2_28_x86_64.whl
#       46.0.4 because that is the version upstream tested the worker with:
#       contrib/swapnet/requirements-tested-runtime.txt at 074dac16 says
#       cryptography==46.0.4, the Windows engine ships the same, and the
#       workflow refuses to build when upstream's file and this one disagree.
#       The manylinux_2_28 build, not the manylinux_2_34 one pip would pick by
#       default on this runner: same code, needs glibc 2.28 where the other
#       needs 2.34, and the package's floor is 2.35. OpenSSL is linked into the
#       wheel statically, so it needs no libssl from the machine and none of
#       OpenSSL's provider directories.
#   cffi-2.1.1-cp314-cp314-manylinux2014_x86_64.manylinux_2_17_x86_64.whl
#       cryptography's bindings load its _cffi_backend extension at import.
#       TIED TO THE PYTHON MINOR VERSION (cp314): move ENGINE_PYTHON_VERSION in
#       the workflow to another minor and this hash must move with it.
#   pycparser-3.12-py3-none-any.whl
#       cffi declares it. Nothing imports it at run time, so it is installed on
#       the build machine and is NOT bundled.
#
