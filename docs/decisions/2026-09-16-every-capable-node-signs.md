## Context

btxscan.io's explorer runs on a trusted mirror. It cannot replay the MatMul
proof, so it accepts a block only when a key it pins has signed it. Four keys
are pinned. One signs: this project's validator, an RTX 3060 in the owner's
home (`cute3060machine`). At 15:23Z on 2026-09-16 that machine was switched
off. The mirror froze at 221,448; the network went to 221,464 and on. A test
transaction sent through the frozen mirror was relayed and mined five minutes
later. Money moved; the explorer and both wallets could not show it, and could
not until the 3060 came back. Seventeen archive nodes on the network helped
nothing: an archive serves signatures and cannot make them. The engine's own
init log had said so daily: "single-key trusted mirror ... configure a second
independent signer".

0.6.23 (2026-09-15) solved the archive half: every GPU-less PC launches as a
keyless trusted mirror and serves history. The signer half had no path through
the app. The one signer was configured by hand in the validator's
`btx_rw.conf` on 2026-09-01, with a key made by hand, and its link to the
mirror was a shell loop.

Measured for this decision, all on 2026-09-16 against the shipped 0.34.6
engine (`v0.34.6-3013c2c2`):

- A missing key file is fatal at init: `Error: Cannot read MatMul attestation
  signing key file`. The engine does not generate one; the app must.
- The key file is one WIF. The validator's begins with `P` and decodes to
  version byte `0x99`, payload 34 bytes, compressed flag set, checksum valid.
  A key generated by `signer::generate_wif` with that version byte, handed to
  btxd offline in a scratch datadir, produced `local_signer: true` with the
  key's public key listed in `trusted_signer_pubkeys`
  (`signer::tests::the_shipped_engine_signs_with_a_generated_key`).
- An attestation at height 221,524 carries the signer's public key as a
  length-prefixed field followed by the DER signature; the window in
  `signer.rs` reads keys by that shape, and a test pins the real bytes.
- The manual peer set the app ships is seven distinct peers for eight engine
  slots (`node::manual_peers`), so one mirror link fits without evicting a
  block source. A test keeps that sum in budget.

## Decision

1. **A node that validates signs, by default.** `signer_enabled` is `true`
   from `NodeAppSettings::default`. The start path generates
   `<datadir>/attestation-signer.key` once (0600, atomic), writes
   `matmulattestationsignerkeyfile=attestation-signer.key` into the conf, and
   keeps the public key for the UI. A host that `launches_as_mirror` (no CUDA
   driver, a refused Mac, the explicit override) gets no key line whatever the
   setting says, and the UI says why.
2. **Existing installs are turned on once, where it means something.**
   `migrate_signer` runs at launch for a settings file that has no
   `signer_enabled` key and has not run before (`signer_migrated`, opposite
   defaults on the serde and struct sides, as `contribution_migrated`). An
   explicit `false` is a choice and stays. The welcome panel is armed only on
   a host that validates; a mirror host records the setting for the day it
   gains a card and is not interrupted.
3. **The link ships with the key.** With a key line in the conf and on the
   validating arm, `build_node_command` adds `-addnode=` for each of
   `signer::BTX_MIRRORS_FED_BY_SIGNERS` (today: btxscan's mirror,
   `20.86.181.203:19338`) and the start path whitelists its IP `noban`. This
   is what makes "send the operator your public key, they add one line" true:
   attestations travel to connected peers and are relayed only by nodes that
   pin the key, so without a direct connection a volunteer's signature never
   arrives.
4. **The role card reads the window, not the setting.** `RecentSigners` keeps
   the newest hundred blocks' signers from `getmatmulattestations`, filled at
   two RPCs per block; the "Signing key" line says "Signing, on N of the last
   M blocks" and turns amber when a configured key is on none of ten or more.
5. **The witness gains `GET /signers/recent`.** The census has no RPC of its
   own; this is the one honest source for "how many distinct keys signed the
   last hundred blocks", and it reads exactly what the role card reads.
6. **Trust is said out loud.** Under the public key: at threshold one a
   pinned key is a full authority; a mirror that pins it takes this node's
   word for the proof of work. The close dialog says what happens to a mirror
   while a signing node is off.

## What this does not do

- It does not pin any new key anywhere. A volunteer's key reaches btxscan only
  when its operator adds `matmultrustedpubkey=<key>` to that mirror and
  restarts it. Fleet mirrors (GPU-less easyNodes) pin
  `BTX_TRUSTED_ATTESTATION_PUBKEYS`, which is a release to change.
- It does not turn a degraded host into a signer. A card the engine does not
  accept validates nothing and therefore signs nothing; the amber line says so
  rather than the setting claiming otherwise.
- It does not make a signer reachable inbound. It makes the signer dial the
  mirror, which is the direction that needs no port forwarding.
- It does not raise the mirror threshold. Two keys at M=1 are two full
  authorities, not a quorum. Moving to M=2 is a separate decision with its own
  measurement (node.rs records why M=2 stalled in August).

## Rollback

- Fleet-wide: set `signer_enabled: false` as the struct default and drop the
  migration's `s.signer_enabled = true`; existing installs keep whatever their
  file says, and `set_signer(false)` removes the conf line at the next start
  without touching the key file.
- One machine: the Settings switch, or `EASYBTX_NODE_TRUSTED_MIRROR=1`, which
  puts the host on the mirror arm where no key line is written.
- The witness route: remove the `["", "signers", "recent"]` arm in
  `witness::route`; the census reads it best-effort and shows nothing when it
  is absent.

## Acceptance, as the owner wrote it

A second operator flips the switch, sends the owner the public key, the owner
adds one line to the mirror's config and restarts it, and from then on btxscan
keeps moving with the 3060 off. Proof: turn the 3060 off for an hour and watch
the mirror track the tip. Not yet run as of this file; the second operator's
key does not exist until 0.6.26 reaches a machine with a capable card.
